# EEG 运动想象三分类项目技术说明

## 1. 项目概述

本项目面向 EEG 脑机接口（BCI）场景，目标是完成 3 类运动想象（Motor Imagery, MI）分类：

- `left`：想象左手运动
- `right`：想象右手运动
- `feet`：想象脚部运动

项目的最终落点是一个可用于在线推理的轻量模型，但当前阶段的核心目标并不是盲目追求复杂模型，而是先通过严格的离线实验回答三个问题：

1. 当前 EEG 数据是否支持稳定的三分类可分性；
2. 哪些预处理和表征方式真正有效；
3. 在避免数据泄露的前提下，什么实验协议最适合当前数据。

这使得本项目的技术价值不仅体现在“模型搭了什么”，更体现在围绕 EEG/MI 特性做出的系统化实验设计与方法学控制。

## 2. EEG 与 MI 的神经生理学动机

EEG 记录的是头皮电极观测到的大脑皮层群体神经元电位变化，具有高时间分辨率，但空间分辨率有限，且容易受到眨眼、体动、导联接触不稳等噪声影响。

运动想象任务主要依赖感觉运动皮层节律变化，最关键的频段包括：

- `mu`：约 `8-12 Hz`
- `beta`：约 `13-30 Hz`

当受试者想象不同肢体运动时，相关脑区会出现 ERD/ERS（event-related desynchronization / synchronization）现象。对分类器而言，真正可利用的信息通常不只来自某个通道瞬时幅值，而更可能来自以下几类模式：

- 特定频带功率变化；
- 左右半球分布差异；
- 多通道协同关系；
- 一段持续时间内节律是否稳定存在。

这也是为什么本项目会优先关注频带选择、时间窗设计、通道交互建模和组级质量控制，而不是直接套用通用深度学习模板。

## 3. 数据协议与任务设计

### 3.1 数据来源

当前项目历史上存在两套协议：

- 旧数据：`500 Hz`，短任务段；
- 新数据：`250 Hz`，长任务段。

在实际对照中，长任务段能提供更稳定的 MI 节律，因此当前主线已明确切换到长 T 数据。

### 3.2 任务定义

旧短 T 协议：

- `B1: 0-10s`
- `T1: 10-15s` 左手
- `B2: 15-25s`
- `T2: 25-30s` 右手
- `B3: 30-40s`
- `T3: 40-45s` 脚
- `B4: 45-55s`

新长 T 协议：

- `B1: 0-10s`
- `T1: 10-20s` 左手
- `B2: 20-30s`
- `T2: 30-40s` 右手
- `B3: 40-50s`
- `T3: 50-60s` 脚
- `B4: 60-65s`

### 3.3 当前主线协议

当前最佳主线基于新长 T 数据，配置如下：

- 采样率：`250 Hz`
- 预处理：`no CAR + 4-30 Hz bandpass + 50 Hz notch`
- 切窗：`4s window + 2s stride`
- 窗口来源：分别从 `T1/T2/T3` 的 10 秒任务段中滑出重叠窗
- 伪迹过滤：`train-fit / val-apply` 的大波动窗过滤
- 评估协议：`LOSO (Leave-One-Group-Out)`

以当前 5 组长 T 数据为例，每个 10 秒任务段在 `4s` 窗、`2s` 步长下可得到 `4` 个重叠窗，因此每组理论上有 `12` 个任务窗，能够在不引入跨组泄露的前提下提升样本利用率。

## 4. 数据泄露控制与质量建模

本项目将“避免数据泄露”作为实验协议设计的核心约束。

### 4.1 组级切分

训练和验证严格按组切分，保证同一组的重叠窗不会同时出现在 train 和 val 中。因此，虽然窗口之间存在时间重叠，但不会形成跨 split 的泄露。

### 4.2 伪迹过滤

为了避免重 ICA 带来的复杂度和不稳定性，当前主线采用更轻量但可追溯的伪迹代理规则：

1. 对训练窗统计 `PTP / RMS`；
2. 用 `median + 3 * MAD` 拟合阈值；
3. 在训练折拟合阈值后，再应用到验证折；
4. 将超阈值的大波动窗视作 blink-like artifact proxy 并过滤。

该设计兼顾了两点：

- 保留 EEG 研究中对伪迹处理的必要性；
- 避免把验证集统计信息反向泄露到训练流程中。

### 4.3 组级质量视角

项目在评估中不仅看总体准确率，也逐组检查：

- 哪些组被伪迹规则大量过滤；
- 哪些组虽然不脏但可分性差；
- 哪些组存在明显质量问题。

这使项目更接近真实 EEG 数据科学流程，而不是单纯围绕总体分数做“堆模型”。

## 5. 预处理探索与结论

项目已系统测试多条预处理路线，包括：

- 带通：`0.5-40 Hz`、`4-30 Hz`、`8-30 Hz`
- 陷波：`50 Hz notch`
- 重参考：`CAR on / off`
- 伪迹处理：基于 `PTP/RMS` 的大波动窗过滤

当前结论是：

1. `4-30 Hz` 比 `0.5-40 Hz` 和 `8-30 Hz` 更契合当前 MI 三分类任务；
2. `8-30 Hz` 过窄时容易丢失部分有效信息；
3. `CAR off` 在当前主线中更稳，说明局部强特异信号可能比全局平均参考更重要；
4. 伪迹过滤必须保留，但不同组之间确实存在显著质量差异。

需要强调的是，主线选择并不只由单次分数决定，而是综合考虑了协议一致性、跨组稳定性、公平评估和后续扩展性。

## 6. 模型路线与当前主线

### 6.1 传统基线

项目已探索 `FBCSP / LDA` 路线，用于回答“小样本 EEG 上传统空间滤波是否更稳”这一关键问题。该基线很重要，因为它能判断深度模型的收益是否真实，而不是由实验设置偏差带来的假优势。

### 6.2 Plain CNN 主线

当前主线模型为轻量 temporal-spatial CNN，代码实现位于 `models/deep/mi_tspnet.py`，主要结构包括：

- 输入：`(batch, channels, time)`
- 多尺度时间卷积：核大小为 `15 / 31 / 63`
- 通道混合：`1x1 Conv` 做空间投影
- 通道注意力：轻量 `SEBlock`
- 全局池化与分类头

这一设计的动机很明确：

- 时间卷积负责建模 mu/beta 节律及其持续性；
- 空间混合负责学习多通道之间的差异模式；
- 模型参数量较小，便于后续在线部署。

### 6.3 已验证但未超越主线的路线

项目还测试了以下方向：

- `contrastive pretraining + fine-tune`
- `focal loss`
- `corr28` 动态相关性输入

这些方向都体现了明确的 EEG 建模动机，但在当前数据规模和协议下，尚未超过 plain CNN 主线。

## 7. 关键实验结果

以下结果来自仓库中的真实消融报告：

- `reports/ablations/cnn_long_t_5groups_250hz_4s_overlap.json`
- `reports/ablations/cnn_long_t_5groups_250hz_4s.json`
- `reports/ablations/cnn_long_t_overlap_focal_contrastive.json`
- `reports/ablations/cnn_long_t_overlap_corr28.json`
- `reports/ablations/cnn_mixed_short_long_250hz_4s.json`

核心结果如下：

| 实验设置 | Accuracy | Balanced Acc | Macro-F1 | 结论 |
| --- | ---: | ---: | ---: | --- |
| 长 T + plain CNN + `4s/2s` 重叠窗 | `0.6154` | `0.6166` | `0.6111` | 当前最佳主线 |
| 长 T + plain CNN + `4s/4s` 独立窗 | `0.4400` | `0.4398` | `0.4320` | 明显弱于重叠窗 |
| 长 T + Focal Loss | `0.5000` | `0.5022` | `0.5100` | 未超过主线 |
| 长 T + Contrastive | `0.5385` | `0.5392` | `0.5262` | 有作用，但仍低于主线 |
| 长 T + corr28 单分支输入 | `0.4615` | `0.4608` | `0.4609` | 不如原始 8 通道 |
| 短 T + 长 T 混训 | `0.4364` | `0.4298` | `0.3946` | 协议混合反而拖累效果 |

这些结果支持了三个非常关键的技术结论：

1. **长任务段优于短任务段**：更长的 MI 持续期能提供更稳定的节律模式；
2. **重叠窗优于独立窗**：在组级 LOSO 下不会引入泄露，同时显著提升样本利用率；
3. **简单、轻量、与 EEG 原理匹配的模型优于更复杂但数据依赖更强的方案**。

## 8. 为什么 `right` 仍然最难

结合当前实验现象，`right` 类识别困难不是单一模型问题，而更可能由以下因素共同导致：

### 8.1 神经生理可分性本身更弱

在当前 8 通道设置下，左/右手的区分主要依赖较细粒度的侧化差异。相比之下，`feet` 往往具有更稳定的节律变化，而 `right` 更容易落在“既不像强左侧化，也不像稳定 feet 模式”的中间地带。

### 8.2 8 通道空间分辨率有限

当前通道数较少，空间采样密度不足，导致模型对左右半球差异的感知能力天然受限。对 `right` 这类更依赖空间细节的类别，影响会比 `feet` 更明显。

### 8.3 `no CAR` 更保留局部强特征，但收益可能偏向更稳定类别

当前主线选择 `CAR off` 是因为它整体更稳、且不易破坏局部特异强信号。但这种收益不一定对三类完全均匀，`left` 或 `feet` 可能从局部强模式中获益更多，而 `right` 仍需要更细的跨通道关系来支撑。

### 8.4 组间差异与数据质量会放大 `right` 的不稳定性

当前数据规模不大，组级异质性对模型边界影响很强。如果 `right` 在部分组中的想象执行不稳定、或更容易受伪迹和姿态变化影响，那么 LOSO 下它通常会成为最先失稳的类别。

## 9. 当前最值得推进的增量创新

基于已有结论，下一步不建议推翻现有体系，而应围绕当前最佳主线做增量改进。

### 9.1 优先方向一：`raw EEG + connectivity` 双分支融合

**理论动机**  
原始波形保留时序节律信息，连接性分支则补充通道协同关系。单独的 `corr28` 输入已经证明“只看连接性会丢失信息”，但它也说明通道间关系本身是有潜力的。

**与 EEG/MI 原理的对应关系**  
MI 不只体现在单通道功率变化，也体现在多通道协同模式和左右侧联动上。双分支结构比单分支更符合这一事实。

**为什么可能优于当前 plain CNN**  
当前 plain CNN 已经能较好提取节律，但对 `right` 这类更依赖细粒度空间关系的类别，加入一个轻量 connectivity 辅助分支可能提升判别边界。

**风险**  
样本量仍偏小，如果 connectivity 分支做得过深，容易过拟合。因此建议把它设计成“辅助分支”而不是替代主分支。

### 9.2 优先方向二：EEGNet 风格的 `temporal -> spatial` 轻量改进

**理论动机**  
EEGNet 类结构先做频段相关的时间卷积，再做深度空间卷积，天然契合 EEG 的“先节律、后拓扑”建模逻辑。

**与 EEG/MI 原理的对应关系**  
MI 信号首先表现为 mu/beta 节律变化，再通过左右侧或跨通道分布体现类别差异。这个顺序和 EEGNet 风格结构高度一致。

**为什么可能优于当前 plain CNN**  
当前主线已具备多尺度时间卷积，但空间混合仍较简单。把空间层从普通 `1x1 Conv` 升级为更有归纳偏置的 EEGNet 风格 block，可能在几乎不明显增参的前提下提升区分能力。

**风险**  
若结构改动过大，会影响和现有主线的公平对照，因此建议只做最小必要改动。

### 9.3 优先方向三：针对 `right` 混淆的局部判别增强

Focal Loss 没有超过主线，说明“全局强调难样本”并不是当前最有效的方向。更合适的思路是做**局部、定向的判别增强**，例如：

- 为 `right vs non-right` 增加一个辅助二分类头；
- 在 embedding 空间增加轻量类间 margin 约束；
- 对 `right` 类引入更细粒度的组级质量权重，而不是统一调 loss。

这种做法比直接替换主损失更符合当前实验结论。

### 9.4 优先方向四：组级质量建模

当前项目已经发现“总体准确率之外，组级质量差异非常关键”。因此下一步可以引入：

- 每组的可用窗比例；
- 每组的 PTP/RMS 异常率；
- 每组预测熵或不确定度；
- 基于质量分数的训练加权。

这类改进不依赖大规模新数据，也更符合真实 EEG 场景。

## 10. 当前最佳结论

在现有全部实验中，当前最可靠的主线是：

- 数据：长 T 协议
- 采样率：`250 Hz`
- 预处理：`no CAR + 4-30 Hz + 50 Hz notch`
- 切窗：`4s window + 2s stride`
- 过滤：`train-fit / val-apply` 的 PTP/RMS 大波动过滤
- 模型：lightweight temporal-spatial CNN
- 评估：组级 `LOSO`

该主线目前优于：

- 独立窗版本；
- 短 T 与长 T 混训；
- Focal Loss；
- Contrastive pretraining + fine-tune；
- 单独的 corr28 动态相关性输入。

## 11. 项目交付价值

从黑客松交付角度看，本项目的亮点不只是“做出了一个 EEG 三分类模型”，而是形成了一套较完整、可解释、可复现实验链路：

1. 从 EEG/MI 神经生理机制出发选择频带与模型；
2. 明确区分短 T 与长 T 协议，不混淆异质数据；
3. 在组级 LOSO 下严格控制重叠窗泄露风险；
4. 用 train-fit / val-apply 的方式实现可追溯伪迹过滤；
5. 通过系统化消融证明当前最佳主线不是偶然结果；
6. 为后续在线推理保留了轻量化模型路径。

因此，这个项目已经具备从“研究验证”继续走向“在线 BCI 原型”的技术基础。

# 三、T5AI 多模态环境反馈硬件系统

## 1. 模块概述

T5AI 硬件模块是 **「一念万象」** 系统的执行终端，负责将 EEG 三分类模型输出的抽象结果转换为可感知的环境反馈。

当上位机识别出 left、right 或 feet 后，会通过开发板自身的 USB 串口向 T5AI 发送场景码。T5AI 再通过统一场景控制器同步切换：

- LCD 场景图片；
- 7 颗 WS2812B 的灯光颜色与动态效果；
- 后续计划加入的对应场景音乐。

完整控制链路如下：

~~~
运动想象 EEG
      │
      ▼
电脑端三分类模型
      │  left / right / feet
      ▼
场景码映射（0 / 1 / 2）
      │  板载 USB 串口
      ▼
T5AI 场景控制器
      ├────────► 3.5 寸 LCD 场景图片
      ├────────► 7 颗 WS2812B 环境灯
      └────────► 场景音乐（后续扩展）
~~~

该模块使脑电分类结果不再停留在软件界面中，而是直接驱动真实环境中的视觉、灯光和声音反馈，形成完整的 BCI 闭环体验。

## 2. 核心硬件组成

### 2.1 Tuya T5AI 开发板

系统主控采用 Tuya T5AI 开发板，芯片架构为 **Arm Cortex-M33**，基于 TuyaOpen 完成固件开发。

T5AI 在系统中主要负责：

- 接收电脑端发送的三分类场景码；
- 校验串口命令并返回执行结果；
- 管理 LCD 图片资源和屏幕刷新；
- 控制 7 颗 WS2812B 的颜色与动态效果；
- 保证图片和灯光在同一场景事件中同步变化；
- 为后续音频播放预留统一触发接口。

T5AI 的 GPIO 逻辑电平为 **3.3 V**。本项目最终采用板载 USB 串口进行通信，不需要再外接 USB-TTL 模块，也不需要额外连接 TX、RX 和 GND 通信线。

T5AI 本身支持 Wi-Fi 和 BLE，项目早期也验证过本地 Wi-Fi TCP 控制方案。考虑到黑客松现场的网络环境、配置成本和连接稳定性，最终选择板载 USB 串口作为电脑到单片机的主要控制链路。

### 2.2 3.5 寸 ILI9488 LCD

显示模块采用 **3.5 寸 ILI9488 LCD**，物理分辨率为 **480 × 320**，使用 RGB 接口和 RGB565 像素格式。

考虑到屏幕在装置中的实际安装方向，固件采用 **320 × 480** 的竖屏逻辑坐标进行显示。三张场景图均来自项目原始图片，仅进行了尺寸、方向和 RGB565 格式转换，没有使用生成式方法重构或改变照片内容。

显示部分具有以下特点：

- 三张原始照片预先转换为 RGB565 固件资源；
- 图片缓冲区存放于 PSRAM；
- 收到场景变化后直接刷新对应帧；
- LCD 背光设置为 **100%**；
- 图片方向与实际倾斜安装方向保持一致。

配套的 GT1151 触控板已由开发板硬件层注册，但当前场景切换以 EEG 串口命令为主，触控功能留作后续本地手动控制扩展。

### 2.3 七颗 WS2812B RGB 灯珠

环境灯光采用 **7 颗串联 WS2812B**。WS2812B 可以对每颗灯珠独立寻址，因此能够同时实现统一色温照明和多颜色动态渐变。

实际连接方式如下：

| WS2812B | T5AI 开发板 | 说明 |
| --- | --- | --- |
| VCC / 5V | 开发板 5V 电源端 | 为灯珠供电 |
| GND | 开发板 GND | 必须共地 |
| DIN | P4 / GPIO4 / SPI1_MOSI | 灯光数据输入 |
| DOUT | 下一颗灯珠的 DIN | 7 颗灯珠依次串联 |

开发板 GPIO 输出为 **3.3 V**，当前原型使用 GPIO4 直接驱动 WS2812B 数据端，并已在短线连接条件下完成实机验证。WS2812B 的 5V 只用于灯珠供电，不能接入 T5AI 的 GPIO。

固件使用 TuyaOpen 像素灯驱动接口控制灯珠，并将全局亮度设置为 **255/255**。7 颗 WS2812B 在全白、满亮条件下的理论最大电流约为 **7 × 60 mA = 420 mA**，因此实际装置必须保证 USB 电源、5V 供电线路和共地连接稳定。

## 3. 板载 USB 串口通信

### 3.1 串口选择

T5AI 开发板通过板载 CH342 提供两路 USB 串口：

- CH342-A：固件下载通道，烧录结束后由 UART0 复用为 EEG 命令数据通道；
- CH342-B：日志通道，用于查看 T5AI 调试信息。

UART0 在芯片内部对应：

- GPIO11：UART0_TX；
- GPIO10：UART0_RX。

由于这些信号已经连接到板载 USB 转串口芯片，用户只需连接开发板 USB 线，不需要手动连接 GPIO10、GPIO11。

Windows 分配的 COM 编号会随电脑和 USB 接口变化，因此电脑端程序不写死任何具体 COM 编号。程序枚举 USB 串口，通过 T5AI 板载 CH342 的 `VID:PID=1A86:55D2` 和 A 通道标识自动定位下载/命令口，并明确排除 CH342-B 日志口。默认配置为 `EEG_DEVICE_SERIAL_PORT=auto`，换电脑或重新插拔导致 COM 编号变化时无需修改配置；只有同时连接多块 T5AI、出现多个 A 通道时，才要求人工指定目标端口。

### 3.2 串口参数

运行时通信参数如下：

| 参数 | 配置 |
| --- | --- |
| 波特率 | 115200 bit/s |
| 数据位 | 8 bit |
| 校验位 | None |
| 停止位 | 1 bit |
| 流控 | 无 |
| 编码 | ASCII |
| 行结束符 | LF，即 \n |

需要特别区分：固件最后一次烧录时使用的 **460800** 是 Flash 下载波特率；EEG 场景命令的运行时波特率始终为 **115200**。

### 3.3 命令与回执

电脑端每次发送一行 ASCII 场景码：

| EEG 分类 | 串口命令 | T5AI 回执 |
| --- | --- | --- |
| left | 0\n | OK 0\n |
| right | 1\n | OK 1\n |
| feet | 2\n | OK 2\n |

T5AI 串口初始化完成后会发送 READY\n。如果收到格式错误或超出范围的命令，则返回 ERR\n。

## 4. 三场景同步设计

项目没有让 LCD、灯光分别响应模型，而是设计了统一场景控制器。一个有效场景码只产生一次场景变化事件，再由该事件同步驱动所有输出设备。

| 场景码 | EEG 结果 | LCD 图片 | WS2812B 效果 |
| --- | --- | --- | --- |
| 0 | left | 暖色场景原图 | 暖橙光，RGB = 255, 95, 10 |
| 1 | right | 明亮场景原图 | 日光白，RGB = 210, 230, 255 |
| 2 | feet | RGB 场景原图 | 七色动态渐变环境光 |

RGB 动态场景采用橙红、橙色、粉色、紫色、蓝色和青色组成的 7 色调色板，在 7 颗灯珠之间连续插值并移动，形成平滑的环境光变化。

系统启动后会以约 6 秒为周期自动展示三个场景，便于脱离电脑演示。当接收到第一条 EEG 串口命令后，自动循环立即停止，系统转入外部控制模式。

为了支持后续音乐播放，场景控制器会记录当前场景。当模型连续输出相同类别时，重复场景不会再次触发图片和灯光切换，也不会在加入音乐后反复从头播放。

## 5. 固件软件架构

T5AI 固件采用 TuyaOpen 的分层外设架构：

- 板级硬件层负责注册 ILI9488 LCD 和 GT1151 触控板；
- 项目自定义 usr_board 层负责注册 7 颗 WS2812B；
- UART0 通过 tal_uart 接口接收电脑端场景码；
- 统一场景控制层负责协调 LCD、WS2812B 和未来音频模块。

核心模块包括：

| 模块 | 功能 |
| --- | --- |
| app_eeg_uart | 接收、解析和应答 0/1/2 串口命令 |
| app_scene_control | 场景去重与多设备同步 |
| app_scene_display | 三张 RGB565 原图的 LCD 刷新 |
| app_ws2812 | 7 颗灯珠的静态色温与动态 RGB 效果 |
| usr_board | WS2812B 的项目级硬件注册 |

这种设计将“分类结果”和“具体硬件输出”解耦。后续无论增加音乐、风扇、香氛或其他智能家居设备，都可以继续挂接在同一个场景变化事件上，而不需要修改 EEG 模型输出协议。

## 7. 音乐扩展方案

音乐模块尚未接入，但 T5AI 板卡具备音频输出能力。需要明确区分：

- MP1/MN1 咪头接口是麦克风输入，只能采集声音，不能播放音乐；
- 音乐播放应使用 LP/LN 扬声器输出端；
- 板载扬声器使能信号为 GPIO28，高电平有效。

后续需要先确认实际扬声器及其阻抗、功率和接口，再加入音频文件存储与播放逻辑。软件上，音乐切换将接入现有的统一场景变化事件，使三种脑电分类能够同步控制图片、灯光和音乐，同时继续利用场景去重机制避免重复重播。
